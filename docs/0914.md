## 3. Enter로 슬래시 메뉴 항목 선택이 안 되던 근본 원인 발견 및 수정

0단계 및 4단계 검증 과정에서, 기존 우회 코드(`pendingEnterHandler` 등)를 지워도 지워도 남아있던 진짜 원인을 특정함:

- `@tiptap/core`의 `ExtensionManager`는 각 extension의 `addKeyboardShortcuts()`를 **extension별로 별도의 keymap 플러그인**으로 만들어 `extensions` 배열 순서대로 등록한다.
- `NotionEditor.jsx`의 `extensions` 배열에서 `CustomHeading`/`CustomParagraph`가 `SlashCommand`보다 먼저 등록되어 있어, 커서가 일반 문단에 있을 때는 `CustomParagraph`의 Enter 커스텀 keymap이 항상 먼저 Enter를 소비(`true` 반환)해버림 → Tiptap `Suggestion`의 `handleKeyDown`은 물론 `SlashCommand`의 옛 우회 코드조차 전혀 호출되지 못하고 있었음.
- **해결**: `SlashCommand.js`의 `Extension.create({...})`에 `priority: 1000`을 추가. Tiptap은 extension을 priority(기본값 100) 내림차순으로 정렬 후 플러그인을 등록하므로, 코드 한 줄 추가만으로 `SlashCommand`의 Suggestion 플러그인이 `CustomHeading`/`CustomParagraph`보다 먼저 Enter를 처리하게 됨(전체 `extensions` 배열 순서를 건드리는 것보다 훨씬 작은 변경).
- 브라우저에서 ArrowDown/Up으로 항목을 고른 뒤 Enter를 눌러 실제로 명령이 실행되는 것을 확인(예: "제목 2" 선택 후 Enter → 실제로 H2 적용됨). 메뉴가 닫힌 상태의 일반 Enter(heading→paragraph 등)도 여전히 정상 동작함을 재확인.

## 4. 최종 검증

- `npm run lint`: 이번에 수정한 3개 파일(`NotionEditor.jsx`, `SlashCommand.js`, `SuggestionList.jsx`)은 신규 오류 없이 기존 사전 존재 오류만 남음. 프로젝트 전체 lint 실패는 이번 작업과 무관한 다른 파일들의 기존 문제(git HEAD 기준으로도 이미 존재).
- `npm run build`: 성공.
- `package.json`/`package-lock.json` 동기화: `npm install` 실행 후 lockfile 루트에 누락됐던 의존성 3줄만 정확히 추가됨(다른 패키지 버전 변경 없음).

- `BlockHandle.jsx`, `useNoteAutosave.js`, `docs/current-plan.md` 등 이번 세션 시작 전부터 있던 다른 미커밋 변경사항은 건드리지 않음.
