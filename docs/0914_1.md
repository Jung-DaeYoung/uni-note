## 5. 2단계: 파일 접근 정책 확정 및 경계 완성

- DB를 직접 조회(노트 본문은 읽지 않고 URL 패턴/메타데이터만 확인)해 실제로 옛 `/uploads/{file}` 정적 경로를 참조하는 노트 3개가 존재함을 확인. → 화이트리스트 호환 정책(A안)으로 진행 결정.
- 조사 중 `ImageUploadController.isAuthorized()`가 "요청에 owner/sig가 없으면 무조건 허용"하던 로직이, 신규 서명 파일에 대해서도 서명 없이 요청하면 그냥 통과되는 별도 우회였음을 추가로 발견.
- `WebConfig.java`(정적 리소스 매핑) 삭제. `ImageUploadController`에 `GET /uploads/{fileName}` 전용 엔드포인트를 추가하고, `file-access.legacy-allowed-files`(application.yaml) 화이트리스트에 등록된 파일만 서명 없이 서빙하도록 변경. 새 파일/기존 파일 모두 서명 우회 완전 차단.
- 실 서버 재기동 후 curl로 라이브 검증: 기존 레거시 3개 파일은 200 유지, 화이트리스트 밖 파일은 신규/구버전 경로 모두 403, 정상 서명 업로드·조회·다운로드 회귀 없음, 경로 조작 시도는 400 유지.

## 6. 3단계: 게시판 강의 접근 권한 확인 및 보완

- `PostService`에 `EnrollmentRepository`를 주입하고 `validateEnrollment()`를 추가해 `getPosts`/`savePost`/`addComment`에 적용. 수강하지 않은 강의 접근은 `CourseAccessException`(403).
- `PostServiceTest` 신규 작성(수강생 성공 3건, 비수강생 거부 3건).
- 실 서버에 임시 강의(수강생 없음)를 만들어 라이브 검증 후 삭제: 미수강 강의 조회/게시글 작성 403, 수강 중인 강의는 정상 200 회귀 확인.
