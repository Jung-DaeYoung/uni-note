## 2. 노트 헤더 퀵 액션 배치

목표: `NotionEditor.jsx` 안에 카드 위 플로팅 pill로 떠 있던 "AI 문제 생성" 버튼과 자동 저장 상태(`Synced/Saving/Error/Retry`)를, `CourseDetailPage.jsx`의 상단 헤더(브레드크럼 옆, 커뮤니티 버튼 앞)로 이동.

- **`CourseDetailPage.jsx`**: `isQuizModalOpen`/`quizResult`/`saveState` state를 새로 보유, `QuizConfigModal`/`CBTPlayer`를 여기서 렌더링, 헤더에 `noteId`가 있을 때만(가드) AI 버튼+저장 상태 pill을 커뮤니티 버튼 앞에 표시. 노트 전환 시 이전 저장 상태가 잠깐이라도 남지 않도록 렌더 중 상태 초기화(React 권장 "adjusting state during render" 패턴 사용, `useEffect` 아님).
- **`NotionEditor.jsx`**: 퀴즈 모달/결과 state와 플로팅 toolbar 전체 제거, 대신 `onSaveStateChange` prop으로 저장 상태를 부모에 보고. 업로드 상태 pill은 위치가 겹치지 않아 그대로 유지.
- **버그 발견 및 수정 — 무한 렌더 루프**: 최초 구현에서 `onSaveStateChange` 콜백 effect의 의존성 배열에 `editor`/`retrySave`를 직접 넣었더니, `CourseDetailPage`의 `onSaved={() => fetchTree()}`가 매 렌더 새 함수라 `useNoteAutosave` 내부 `performSave`→`debouncedSaveToServer`→`retrySave` 체인이 매번 재생성되고, 이것이 다시 부모의 `setSaveState`를 유발해 무한 재렌더로 이어짐("Maximum update depth exceeded"). 원인을 재현 스크린샷(헤더가 화면 전체에 타일링되는 CDP 렌더 버그로 오인했다가 콘솔 확인 후 진짜 원인 특정)과 `git stash`로 원본 코드와 비교해 확정.
  - 수정 1: `CourseDetailPage`에서 `onSaved`를 `useCallback`으로 안정화.
  - 수정 2: `NotionEditor`의 보고 effect를 `saveStatus` 변경에만 반응하도록 바꾸고, `editor`/`retrySave`는 매 렌더 갱신되는 `ref`로 참조(ref 갱신 자체는 렌더 중이 아닌 별도 `useEffect`에서 수행 — `react-hooks/refs` lint 규칙 위반 방지).
- **라이브 검증**: 헤더 순서(`[브레드크럼] ... [AI 문제 생성] [● Synced] [커뮤니티]`) 확인, 노트 미선택 화면(`/course/:courseId`)에서 AI 버튼·저장 상태 가드 동작 확인, AI 문제 생성 모달이 `NoteTreeProvider` 컨텍스트 정상 접근, 노트 전환 시 무한 루프 없음(수정 전/후 콘솔 에러 비교로 재확인), 다크/라이트 모드 모두 정상.

## 3. 스마트 오답 복습·취약 개념 리포트

`docs/current-plan.md`가 이 기능 계획으로 전면 교체되어 새로 진행. 오답노트에 통계 집계(문제별/강의별/유형별 정답률, 반복 오답)와 규칙 기반 복습 우선순위, "오늘의 복습" 추천을 추가해 `QuizLibraryPage`의 오답노트 탭을 확장했다. AI 기반 분석(계획서 7단계)은 이번 범위에서 제외.

### 선행 수정 — 오답 재풀이 결과 미저장 버그(검증 후 발견)

- `IncorrectNoteService.getPracticeSession()`이 반환하는 가상 `quizSetId(-1L)`을 `CBTPlayer.jsx`가 그대로 `POST /quiz/attempts`에 보내면, `QuizService.saveAttempt`가 `quizSetRepository.findById(-1L)`에서 404를 던지고, 프론트가 이 오류를 `console.error`로만 남기고 `setSubmitted(true)`를 호출해 **사용자에게는 정상 제출로 보이지만 실제로는 풀이 기록이 전혀 저장되지 않던** 기존 버그를 코드 추적으로 확인(직접 읽어 검증).
- 이번에 새로 만드는 "오늘의 복습"도 동일한 `-1L` 관례를 재사용하므로 그대로 두면 똑같이 깨짐 — `saveAttempt`가 `quizSetId`가 없거나 음수면 `quizSet=null`로 저장하고 문제 단위로 소유권을 검증하도록 수정(`QuizAttempt.quizSet`은 원래 nullable이라 마이그레이션 불필요). 지정된 `quizSetId` 경로에도 없던 소유권 검증을 함께 추가.
- 읽기 경로(`convertToAttemptResponses`, `getAttemptDetail`)에 `quizSet == null` null 가드 추가(제목 "오답 복습", `courseId`/`quizSetId` null로 폴백).

### 백엔드

- **`IncorrectNoteService.addToGroup`**: 문제가 요청 학생 본인의 퀴즈에 속하는지 검증하는 로직 추가(기존에는 다른 학생의 문제 ID를 알면 자신의 오답노트에 추가할 수 있는 gap이 있었음).
- **신규 집계**: `UserAnswerRepository.aggregateByQuestionForStudent` — 학생 범위 단일 GROUP BY 쿼리로 문제별 시도/정답/오답 수, 마지막 풀이일/오답일을 한 번에 집계(신규 projection `QuestionAnswerStat`). 전체/강의별/유형별/문제별/오늘의 복습 다섯 응답이 모두 이 한 쿼리 결과를 공유해 숫자가 서로 어긋나지 않게 설계.
- **신규 엔드포인트**(`IncorrectNoteController`, `/api/quiz/incorrect` 하위): `GET /summary`, `GET /statistics/courses`, `GET /statistics/types`, `GET /questions`, `GET /review-today?limit=&courseId=`.
- **복습 우선순위 규칙**(`IncorrectNoteService`): 반복 오답(≥2회) 또는 최근 오답 또는 정답률<50% → HIGH, 정답률 50~75% → MEDIUM, 그 외 LOW. 정렬은 반복 오답 수desc → 최근 오답 여부desc → 마지막 풀이일asc → 문제ID asc(생성일 컬럼이 없어 IDENTITY 채번 순서로 근사). 계획 문서의 HIGH/MEDIUM 조건이 서로 배타적이지 않게 쓰여 있어 HIGH 우선 판정으로 단순화(판단 근거로 플랜 문서에 명시).
- **신규 DTO 6개**: `ReviewPriority`, `IncorrectSummaryResponse`, `CourseIncorrectStatResponse`, `QuestionTypeIncorrectStatResponse`, `IncorrectQuestionStatResponse`, `TodayReviewQuestionResponse`.
- **신규 테스트**: `QuizServiceTest`에 가상 세션 저장/소유권 검증/null-세이프 조회 5건, `IncorrectNoteServiceTest`에 소유권 검증 1건 + 통계·우선순위·정렬·limit·courseId 필터·빈 결과 등 7건 추가. 전체 스위트 `BUILD SUCCESSFUL` 유지.
