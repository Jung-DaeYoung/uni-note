## 3. `isAuthor`/`author` 중복 JSON 필드 수정

- `CommentResponse`/`PostResponse`의 `boolean isAuthor` 필드에 `@JsonProperty("isAuthor")`를 붙인 구조가, Jackson이 필드명(`isAuthor`, 그대로 유지)과 getter명(`isAuthor()` → `is` 스트립 후 `author`로 인식)을 서로 다른 프로퍼티로 취급해 응답 JSON에 `author`/`isAuthor`가 중복 직렬화되는 문제를 발견(Jackson-databind로 직접 재현해 원인 확정).
- 두 DTO 모두 필드명을 `author`로 바꾸고 `@JsonProperty("isAuthor")`로 wire 이름만 고정 — getter(`isAuthor()`)와 필드의 암묵적 이름이 일치해 하나의 프로퍼티로 병합됨.
- 빌더 호출부(`PostService`, `DashboardService`)의 `.isAuthor(...)` → `.author(...)`로 함께 수정. JSON 계약(키 이름)은 그대로라 프론트엔드 변경 없음.

## 5. `docs/current-plan.md` 재검토 (오답노트 원문 블록 표시 계획)

사용자가 새 계획("오답노트 원문 블록 표시 기능 설계")으로 문서를 갱신, Explore 서브에이전트 2개(프론트 스크롤/하이라이트 흐름, 백엔드 `sourceNoteId`/`sourceBlockId` 데이터 모델) + 직접 코드 확인으로 전량 검증. 전체 방향은 정확했으나 5곳을 보정:

1. "성공 시 state 정리"는 `useSourceBlockScroll.js:23`에 이미 구현되어 있었음 — 실제 남은 일은 실패 경로 정리 누락, 쿼리스트링 미보존, 안쪽 3000ms 타이머가 cleanup에서 취소 안 되는 실제 버그로 범위를 좁힘.
2. 왼쪽 accent bar(`NotionEditor.jsx`의 `.origin-highlight::before`)는 이미 있었음 — 신규 작업은 `prefers-reduced-motion` 처리뿐임을 명시.
3. `sourceBlockId` 누락은 희귀 예외가 아니라, AI 생성 스키마(`QuizAiGenerationService`)의 `required` 목록에 `sourceNoteId`/`sourceBlockId`가 없어 실제로 흔히 발생할 수 있음을 근거와 함께 반영.
4. `TodayReviewList`는 필드를 직접 참조하지 않고 `useIncorrectNotes.handleViewReviewSource`가 실질 로직을 담당한다는 사실 추가.
5. `sourceBlockId`가 현재 라우터 state 키로는 전혀 쓰이지 않는다는 것(실제는 `scrollToBlockId`)과, 이름 통일이 3개 파일(`useIncorrectNotes.js`/`CBTPlayer.jsx`/`useSourceBlockScroll.js`)을 함께 고쳐야 하는 실제 리팩터임을 명시.

## 6. 오답노트 원문 블록 표시 기능 구현

5번 계획대로 구현:

- **라우팅 state**: 두 호출부(`useIncorrectNotes.js`, `CBTPlayer.jsx`) 모두 `sourceBlockId`(+`sourceNavigationId`)를 전달하도록 전환, 훅은 기존 `scrollToBlockId`도 fallback으로 계속 지원. `courseId`/`sourceNoteId`/`sourceBlockId` 누락 시 안내 후 이동하지 않도록 가드 추가.
- **블록 탐색**(`useSourceBlockScroll.js` 전면 재작성): 고정 800ms 단발 체크 → `requestAnimationFrame` 기반 최대 2초 폴링. 전역 `document.querySelector` 대신 `editor.view.dom`(해당 Tiptap 에디터 인스턴스 DOM)으로 범위를 좁혀 다른 화면의 동일 `data-id`와 충돌하지 않게 함. 2초 내 못 찾으면 안내 후 state 정리.
- **하이라이트**: 기존 accent bar·배경 페이드 유지, `prefers-reduced-motion: reduce`에서는 애니메이션 없이 정적 배경만 표시하도록 CSS 추가. 블록을 찾으면 `tabindex=-1` + `focus()`로 키보드/스크린리더 사용자도 위치를 인지하도록 함.
- **cleanup**: 실패 경로에서도 state 정리하도록 추가, 정리 시 `location.search`(쿼리스트링) 보존, effect cleanup에서 하이라이트 제거용 안쪽 타이머까지 함께 취소(빠른 노트 전환 시 이전 타이머 미취소 버그 수정).
- 검증: `npm run lint` / `npm run build` / `npm run test -- --run`(47개 테스트) 모두 통과.

## 7. 퀴즈 삭제 500/409 에러 원인 분석 및 수정

사용자가 학습 보관함에서 퀴즈 삭제 시 `DELETE /api/quiz/23` 500을 보고, 로컬 백엔드 로그(`backend-run.log`)의 스택 트레이스로 원인을 바로 특정:

- **1차 원인**: `QuizSet.questions`는 cascade로 함께 삭제되지만, `IncorrectNoteItem`(오답노트 항목)은 `IncorrectNoteGroup`에 속한 별개 aggregate이면서 `question_id`로 `Question`을 참조해 FK 제약 위반 발생.
  - 수정: `IncorrectNoteItemRepository.deleteByQuestion_QuizSet_QuizSetId` 추가, `QuizService.deleteQuiz`에서 `QuizSet` 삭제 전에 먼저 호출.
  - `GlobalExceptionHandler`에 `DataIntegrityViolationException` → 409 핸들러 추가(원인 불명 500 대신 명확한 응답, 방어적 조치).
  - 로컬 DB에 재현 fixture(퀴즈+문제+오답노트 항목)를 만들어 수정 전 500 → 수정 후 204 및 관련 행 정리까지 직접 확인.
- **2차 원인**(1차 수정 후에도 실제 quiz 23에서 409 재발): `user_answers`도 `question_id` FK를 가지는데, 오답노트 다시풀기/오늘의 복습 같은 "가상 세션"은 `QuizAttempt.quizSet`이 `null`이라 `QuizSet.attempts` cascade 트리 밖에 있어 정리되지 않고 있었음. 실제 quiz 23(사용자 계정 소유, "DevOps 기본 개념 정리")에 문제 3개·답안 16건이 걸려있던 것을 DB로 확인.
  - 수정: `UserAnswerRepository.deleteByQuestion_QuizSet_QuizSetId` 추가, `deleteQuiz`에서 동일하게 먼저 정리.
  - 가상 세션 답안이 걸린 재현 fixture로 수정 전 409 → 수정 후 204 확인.
- `QuizServiceTest`에 두 레포지토리 호출 검증 추가, `./gradlew test` 전체 통과.
- 재현·검증에 쓴 fixture(퀴즈/문제/오답노트 항목/가상 세션 답안)는 모두 정리, 실제 사용자 데이터(quiz 23)는 건드리지 않고 코드 수정 후 백엔드 재시작까지만 진행 — 최종 삭제 재시도는 사용자 본인 계정으로 확인 필요.
