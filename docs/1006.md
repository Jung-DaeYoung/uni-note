## 1. CBT 시험 공유게시판 (`cfbdebb`)

생성한 퀴즈를 같은 강의 수강생과 공유해 풀 수 있는 게시판이다. 왼쪽 메뉴 이름은 "CBT 시험 공유게시판"이다.

### 요구사항

- 최신순·추천순·조회순 정렬
- 👍 추천(토글)
- 다른 사람이 공유한 시험의 문제마다 내 오답노트에 담기
- 원문 보기는 제공하지 않는다.
- 사용자 추가 요구: A가 원본 퀴즈를 삭제해도, A가 게시판 글을 삭제해도 B의 오답노트는 유지되어야 한다.

### 설계: 공유 시점 스냅샷 복사

처음 설계는 원본 QuizSet을 그대로 참조하는 방식이었다. 위 삭제 요구를 반영해 스냅샷 방식으로 바꿨다.

- 공유하면 원본 QuizSet·Question을 새 QuizSet으로 복사한다.
  - 복사본의 `student`는 null(소유자 없음)이다. 그래서 공유한 사람의 "나의 CBT 시험"에 중복으로 나타나지 않는다.
  - 복사할 때 `sourceNoteId`/`sourceBlockId`를 비운다. CBTPlayer는 출처가 없으면 "원문 보기"를 숨기므로 별도 마스킹 코드가 필요 없다.
- 원본 삭제(`QuizService.deleteQuiz`)는 원본 quizSetId만 지우므로 복사본과 B의 기록에 영향이 없다. 코드는 바꾸지 않았다.
- 게시판 글을 삭제하면 `SharedQuiz`와 추천만 지우고 복사본은 남긴다. B의 오답노트·풀이 기록이 복사본을 참조하기 때문이다.
  - 아무도 참조하지 않는 복사본도 남는다(`ponytail:` 주석).

### 구현

- 엔티티 `SharedQuiz`(`shared_quizzes`), `SharedQuizLike`(`shared_quiz_likes`)
  - 추천수·조회수는 컬럼 카운터로 두고 `@Modifying` JPQL로 원자적으로 증감한다.
  - `sourceQuizSetId`는 FK가 아닌 값이다. 원본이 지워져도 남고, 중복 공유 방지와 "공유됨" 표시에 쓴다.
- API `/api/shared-quizzes`

  | Method | Path | 동작 |
  |---|---|---|
  | GET | `?sort=latest\|likes\|views&courseId=` | 목록 |
  | POST | `{quizSetId}` | 공유 |
  | GET | `/{id}` | 상세(조회수 +1) |
  | DELETE | `/{id}` | 글 삭제 |
  | POST | `/{id}/like` | 추천 토글 |

  - 수강 강의의 글만 보이고, 작성자는 `익명 N`(`PostService.anonymousName` 재사용)으로 표시한다.
- 접근 규칙 `SharedQuizService.canAccessQuestion`: 아래 중 하나면 남의 문제를 풀고 오답노트에 담을 수 있다.
  1. 게시 중인 복사본의 문제이고 그 강의를 수강 중
  2. 이미 풀어 본 문제
  3. 내 오답노트에 담긴 문제

  2·3이 있어서 글이 삭제된 뒤에도 B는 재풀이·오늘의 복습을 계속 저장할 수 있다.
- `QuizService.saveAttempt`, `IncorrectNoteService.validateQuestionOwnership`가 이 규칙을 쓴다.
- `QuizService.validateOwnership`은 owner가 null이면 403을 던진다. 복사본 ID로 `/api/quiz/{id}`를 조회·삭제할 때 500이 나지 않게 하기 위해서다.
- `QuizSetResponse`에 `shared` 필드를 추가했다(필드 추가만).
- 프론트
  - `SharedQuizBoardPage`: 정렬 탭, 강의 필터, 카드, 👍, 풀기, 내 글 삭제
  - `useSharedQuizzes` 훅
  - 나의 CBT 시험 카드에 [공유] 버튼과 "공유됨" 배지

## 4. 오늘의 복습 간격 반복 (`30d5b99`)

학습 기능 추천 보고에서 1순위로 제안한 작업이다.

### 기존 문제(코드로 확인)

- 2번 이상 틀린 문제는 이후 계속 맞혀도 영원히 HIGH였다(`incorrectCount >= 2`). 그래서 복습 목록이 줄지 않았다.
- 한 번 LOW가 된 문제는 다시 나오지 않았다.
- 날짜 계산이 없어 오늘 이미 푼 문제도 계속 나왔다.

### 변경

- 마지막 오답 이후 연속 정답 수(streak)에 따라 `마지막 풀이일 + 1·3·7·14·30일`에 다시 낸다.
  - 연속 5회 정답이면 졸업이다.
  - 한 번이라도 틀린 문제만 대상이다.
- 새 테이블·컬럼 없이 `UserAnswerRepository.findAnswerHistoryForStudent`(시간순 정답 여부)로 계산한다. 운영 DDL이 필요 없다.
- `getTodayReview`, 요약의 `reviewTargetCount`, 강의별 `reviewTargetCount`를 같은 규칙으로 통일했다.
  - 정렬은 기존 `PRIORITY_ORDER`를 유지했다(기존 정렬 테스트 보존).
- 응답 `TodayReviewQuestionResponse`에 `nextReviewAt`, `streak`를 추가했다.
- 화면
  - 오늘의 복습에 "n일 밀림"/"오늘 복습", "연속 정답 k회"를 표시한다.
  - 빈 목록 문구는 "오늘 복습할 문제를 모두 끝냈어요."다.
- 재풀이 창을 닫으면 통계·복습 목록을 다시 불러오게 했다(`useIncorrectNotes.closePractice`). 브라우저 테스트에서 닫아도 목록이 줄지 않던 것을 발견해 함께 고쳤다.
- 날짜 계산은 `Clock`을 주입해 테스트에서 2024-01-12로 고정했다. 테스트 4개를 추가했다.
  - 어제 오답 → 오늘 도래
  - 오늘 오답 → 내일
  - 1회 정답 → 3일
  - 2회 오답 후 5회 연속 정답 → 졸업(기존 버그 회귀 방지)
- 브라우저 확인
  - 풀이 기록을 3일 전으로 옮긴 테스트 계정에서 4문제가 "2일 밀림"으로 나왔다.
  - 다시 풀어 맞히자 목록과 카드 숫자가 4 → 3 → 2로 줄었다.

## 5. 공유 시험 문제별 댓글 (`58a0b6b`)

- 공유 시험을 제출한 뒤 결과 화면에서 문제마다 익명 댓글을 작성·조회·수정·삭제한다.
  - 풀이 중에는 정답 노출을 막기 위해 보이지 않는다.
- 엔티티 `SharedQuizComment`(`shared_quiz_comments`)
  - `SharedQuiz.comments`에 cascade를 걸어, 글을 삭제하면 댓글도 함께 삭제된다.
- API
  - `GET /api/shared-quizzes/{id}/comments`: 문제별로 묶어 한 번에 받는다.
  - `POST /{id}/questions/{questionId}/comments`
  - `PUT /comments/{commentId}`
  - `DELETE /comments/{commentId}`
  - 강의 게시판의 `CommentRequest`/`CommentResponse`를 재사용했다.
- 권한
  - 작성·조회는 수강생만, 수정·삭제는 작성자 본인만 할 수 있다.
  - 다른 시험의 문제에 쓰면 400이다.
- 프론트
  - `QuestionComments` 컴포넌트를 추가했다.
  - CBTPlayer에 선택 prop `sharedQuizId`를 추가했다. 공유게시판에서 연 경우에만 댓글이 보인다.
- 테스트
  - `SharedQuizServiceTest`에 5개를 추가했다.
  - 브라우저 확인(계정 4개)
    - 1003 작성 → 1004에게 익명으로 보이고 수정·삭제 버튼 없음
    - 1004 작성
    - 1003 수정·삭제
    - 1002 글 삭제 → DB에서 댓글 0건, 복사본은 유지
