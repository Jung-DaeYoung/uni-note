## 2. 노트 공유 게시판 (`bfa502b`)

노트와 그 하위 노트를 같은 강의 수강생에게 읽기 전용으로 공유하는 게시판이다. 사이드바 "CBT 시험 공유게시판" 아래 "노트 공유 게시판" 메뉴로 들어간다.

### 계획 검토에서 고친 점

- **첨부 파일 403 우려는 사실이 아니었다.** `FileAccessSigner` 서명은 (파일명, 업로더 학번)으로만 만들고 요청자를 검증하지 않는다. 노트 본문의 서명 URL이 스냅샷에 그대로 복사되므로 다른 수강생도 열람된다.
- 하위 노트 조회용 새 repository 메서드는 필요 없었다. 기존 `findByCourseAndStudentOrderByCreatedAtAsc`로 한 번에 읽고 메모리에서 트리를 만든다.
- 선례인 CBT 시험 공유게시판(`SharedQuiz*`)을 그대로 따르도록 명시했다.
- 결정: 제목은 루트 노트 제목 자동 사용, 댓글 수정 지원, 페이지네이션 없음, 공유 해제는 즉시 삭제.

### 구현

- 엔티티
  - `SharedNotePost`(`shared_note_posts`): 원본 루트 노트 ID를 FK가 아닌 unique 값으로 보관(중복 공유 방지)
  - `SharedNoteSnapshot`(`shared_note_snapshots`): 공유 시점의 노트 한 장(제목·본문)
    - 부모 관계는 자기참조 FK 대신 원본 노트 ID 값(`parentOriginalNoteId`)으로 보관했다. cascade 삭제 순서에 따른 FK 위반을 피하기 위해서다.
  - `SharedNoteComment`(`shared_note_comments`)
  - 글을 삭제하면 스냅샷·댓글도 함께 지운다.
- API `/api/shared-notes`

  | Method | Path | 동작 |
  |---|---|---|
  | GET | `?courseId=` | 수강 강의의 글 목록(최신순) |
  | POST | `{rootNoteId}` | 본인 노트와 모든 하위 노트를 스냅샷으로 공유 |
  | GET | `/{postId}` | 스냅샷 트리 상세(수강생만) |
  | DELETE | `/{postId}` | 글 삭제(작성자만) |
  | GET·POST | `/{postId}/comments` | 댓글 조회·작성(수강생만) |
  | PUT·DELETE | `/comments/{id}` | 댓글 수정·삭제(댓글 작성자만) |

  - 원본 노트 API(`/notes/{id}`)의 작성자 전용 권한은 그대로 둔다.
- 프론트
  - 노트 화면 헤더에 "노트 공유" 버튼(저장이 끝난 상태에서만 활성)
  - `/shared-notes`(목록), `/shared-notes/:postId`(읽기 전용 상세)
  - 읽기 전용 뷰어는 `NotionEditor`를 쓰지 않는다. 자동 저장·localStorage 복구가 원본 noteId로 동작하기 때문이다. 대신 `NotionEditor`의 스키마 확장(`noteSchemaExtensions`)과 스타일(`NoteEditorStyles`)을 export해 같은 모양으로 그린다.
  - 댓글 UI는 `QuestionComments`의 고정 URL을 props로 바꿔 CBT와 함께 쓴다.

### 테스트

- 백엔드 단위 테스트 13개(`SharedNoteServiceTest`)
- 계정 1001~1005로 API 시나리오 43개 통과
  - 공유·중복 공유·남의 노트 공유, 원본 수정·삭제 후 스냅샷 유지, 댓글 권한, 미수강 학생(1004 수강을 잠시 해제) 차단, 삭제 후 404, 삭제 cascade
- 브라우저: 공유 버튼, 목록, 읽기 전용 상세, 트리 이동, 본문 페이지 링크, 댓글 작성·수정, 작성자 삭제

## 3. 사용자 직접 생성 강의 (`9b096ee`)

학교 수강 강의 외에 사용자가 강의명만으로 자기 강의를 만들고, 그 안에서 기존 노트 기능을 그대로 쓰는 기능이다.

### 계획 검토에서 고친 점

- `DashboardService`가 `getProfessor().getName()`을 바로 호출해, 교수가 없는 강의가 섞이면 대시보드 전체가 500이 된다 → 서버에서 null 처리.
- `QuizService`·`IncorrectNoteService`는 수강 여부가 아니라 소유권만 검사해서 수정이 필요 없었다. 수강 검사는 `NoteService`(변경), `DashboardService`(목록 추가), `PostService`·`SharedQuizService`·`SharedNoteService`(직접 생성 강의를 자동 차단, 그대로 둠)뿐이다.
- `ownedByMe` 필드는 불필요(목록에는 본인 강의만 나옴). `userCreated` 하나로 충분하다.
- 결정: 이름 중복 허용, 게시판·공유 미제공, 삭제 시 학습 데이터까지 함께 삭제, soft delete 없음.

### 구현

- `Course`에 `owner`(소유자)와 `userCreated` 추가. 소유자에게는 `Enrollment`를 만들지 않는다.
- API `/api/courses`: POST(생성), PUT `/{id}`(이름 변경), DELETE `/{id}`(삭제). 본인이 만든 강의만, 학교 강의는 403.
- `NoteService`는 "수강 중이거나 본인이 만든 강의"면 노트 접근을 허용한다.
- 삭제 순서: 소유자의 이 강의 퀴즈마다 기존 `QuizService.deleteQuiz`(오답노트 항목·답안 정리 포함) → 루트 노트(하위 노트 cascade) → 강의.
- 직접 만든 강의의 노트·퀴즈를 공유하면 "직접 만든 강의는 공유할 수 없습니다"(400).
- 프론트
  - 사이드바 "현재강의목록"을 "강의목록"으로 바꾸고 "수강 중인 강의"/"내가 만든 강의"로 나눴다.
  - "내가 만든 강의" 옆 + 버튼을 누르면 VS Code 새 파일처럼 목록 안에 이름 입력칸이 생긴다. Enter·포커스 이탈로 생성(한 번만), Esc·빈 이름은 취소. 한글 조합 중 Enter는 제출하지 않는다.
  - 강의 화면 헤더에 "이름 변경"·"강의 삭제" 버튼. 커뮤니티·노트 공유 버튼은 숨긴다.
  - 대시보드에는 수강 강의만 보이고, 공유 게시판 강의 필터에서도 직접 만든 강의를 뺀다.
  - 처음에는 대시보드에 "내가 만든 강의" 섹션(입력 폼·카드)을 만들었으나, 사용자 피드백으로 사이드바 인라인 생성 방식으로 다시 설계했다.

### 수동 테스트에서 찾아 고친 버그

- **직접 만든 강의에 들어가면 탭이 멈추고 대시보드로 튕겼다.** 강의 화면이 열리자마자 게시판 글을 요청(`useCourseBoard`)하는데, 직접 만든 강의는 403이 되고 `client.js`의 공통 403 처리가 알림 후 대시보드로 보낸다. 학교 강의로 확인된 뒤에만 게시판을 불러오도록 `enabled`를 추가했다.
- **사이드바에서 `/course/1`과 `/course/10`이 함께 선택돼 보였다.** 경로 앞부분만 비교(`includes`)하던 기존 버그로, `/course/{id}/`까지 비교하도록 고쳤다.

### 테스트

- 백엔드: `CourseServiceTest` 5개, 대시보드(교수 null)·노트(소유자 접근)·공유 400 테스트 추가
- 실제 DB API 시나리오 30개 통과. 퀴즈·풀이 기록·오답노트가 있는 강의도 FK 오류 없이 삭제됐다(퀴즈 세트는 AI 생성 대신 SQL로 만들었다).
- 브라우저: 강의 생성·자동 첫 노트·노트 자동 저장·이름 변경·삭제, 다른 계정의 직접 접근 차단, 학교 강의 화면 회귀, 게시판 필터

## 4. 원문 보기 하이라이트 수정 (`fc80ceb`)

오답노트·CBT 결과에서 "원문 보기"를 누르면 노트로 이동은 되지만 해당 블록 하이라이트가 보이지 않았다.

### 원인

- `useSourceBlockScroll`이 에디터 안 블록 DOM에 `class`·`tabindex`를 직접 붙였다.
- ProseMirror는 편집 가능한 에디터 DOM의 속성 변경을 감지하면 그 노드를 문서 상태대로 다시 그린다(`prosemirror-view` `DOMObserver.registerMutation`). 그래서 붙인 class가 거의 즉시 사라졌다.
- 하이라이트 도입 때부터 같은 방식이었다. 오늘 작업으로 생긴 문제는 아니다.

### 수정

- 새 확장 `SourceHighlight`: ProseMirror 노드 데코레이션으로 `origin-highlight` class를 그린다. 노드를 다시 그려도 유지되고, 편집으로 위치가 밀려도 같은 블록을 따라간다.
- 블록은 DOM 대신 문서(`attrs.id`)에서 찾고, `tabindex` 대신 블록 안으로 커서를 옮겨 위치를 알린다.
- 대기 폴링을 `requestAnimationFrame`에서 `setTimeout`으로 바꿨다. `requestAnimationFrame`은 가려진 탭에서 멈춘다.

### 테스트

- 단위 테스트 1개: 앞 블록을 편집해도 하이라이트가 남고, 해제하면 사라지는지 확인
- 브라우저: 0.27초에 해당 블록에 적용, 3초간 유지, 커서 위치, 3초 뒤 해제, CSS 계산값(배경 페이드 3초, 왼쪽 파란 막대 4px) 확인

## 5. 공유 노트 화면 정리 (`311b71d`)

공유 노트 상세 왼쪽의 노트 트리가 하위 노트가 없으면 제목 하나만 반복해 보여 줬다.

- 하위 노트는 본문 페이지 링크로 이동하므로(하위 노트는 "/" 명령으로만 생성되고 그때 부모 본문에 링크가 들어간다) 트리를 없애고 본문을 전체 폭으로 보여 준다.
- 하위 노트를 볼 때만 본문 위에 경로(`루트 › 1장 › 1.1절`)를 보여 주고, 눌러서 상위 노트로 돌아간다.
- 3단 공유 노트로 링크 이동·경로 복귀를 브라우저에서 확인했다.
