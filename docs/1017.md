## 1. 마이페이지 2차 (`92e0466`, `2b7aaa3`)

### 2차 응답 필드 (`GET /api/mypage`)

`courseProgress`, `recentActivities`, `myContents`를 추가했다.

- **강의 목록:** 대시보드와 같은 원천(수강한 강의 + 직접 만든 강의)을 쓴다. 활동이 없는 강의는 0으로 보인다.
- **최근 활동:** 원천별로 최신 20건씩 모아 합친 뒤 20건만 남긴다.
  - 오답 문제 텍스트 같은 긴 제목은 40자로 자른다.
  - 공유 노트 댓글과 공유 시험 댓글은 `SHARED_NOTE_COMMENTED`, `SHARED_QUIZ_COMMENTED`로 구분한다.
  - 게시글·댓글 활동을 누르면 `?postId=`로 강의 게시판의 해당 글이 열린다.
- **내 콘텐츠:** 최근 생성한 퀴즈 6개(`recentQuizzes`)를 보여 준다. 누르면 `/quizzes`로 간다.

### 테스트

App 라우팅 테스트에 두 경우를 추가했다.

- 로그인하지 않고 `/mypage`에 가면 리다이렉트된다.
- 로그인한 상태에서는 `/mypage`에 직접 접근할 수 있다.

## 2. AI 문제 생성 고도화

프롬프트를 바꿀 때마다 `PROMPT_VERSION`을 올렸다(`2026-10-17.1` → `.4`).

### P2-1 1단계: 개념 태그와 학습 목표 (`c71b71c`)

- **저장과 응답:** `Question.conceptTags`(JSON TEXT)를 추가했다.
  - 응답 필드는 `QuestionResponse.conceptTags`이고, 기존 문제는 빈 배열로 응답한다.
  - 공유 스냅샷에도 태그를 복사한다.
- **생성:** Gemini 스키마에서 `conceptTags`는 필수다.
  - 검증기는 태그의 공백·중복·길이만 정리한다. 이것을 재생성 사유로 쓰지는 않는다.
- **학습 목표:** `QuizRequest.learningObjectives`(선택, 최대 5개·각 100자)를 프롬프트에 반영한다.
- **화면:** 생성 창에 학습 목표 입력란을 두었다. CBT 결과 화면에는 개념 태그를 보여 준다.
- **운영 DDL:** `ALTER TABLE questions ADD COLUMN concept_tags TEXT NULL` (`docs/database.md`에 기록)

### P2-3 2단계: 개념별 정답률 (`8464204`)

- **API:** `GET /api/quiz/incorrect/statistics/concepts`는 (강의, 개념 태그)별 풀이 통계를 준다.
- **태그 묶기:** 대소문자를 무시하고 묶는다.
  - 표기는 가장 먼저 만든 문제의 것을 쓴다.
  - 한 문제에 태그가 여러 개면 각 태그에 모두 합산한다.
- **계산:** 블록 통계와 같은 합산·취약도 계산(`totalsOf`)을 쓴다.
- **화면:** 오답노트 개요에 취약 개념 카드를 추가했다. 상위 8개 개념의 정답률과 풀이 수를 보여 준다.

### P2-4: 취약 개념 집중 출제와 생성 모드 (`f045594`, `708f06c`)

- **1단계:** `QuizRequest.focusConcepts`(선택, 최대 5개·각 30자)를 추가했다.
  - 생성 창은 현재 강의의 취약도 HIGH 개념을 최대 5개 불러온다. 사용자가 하나씩 해제할 수 있다.
  - 같은 문제를 반복하지 않고 비교, 사례 적용, 오개념 판별 형태로 낸다.

- **2단계:** 생성 창에 모드 4개를 두었다.

## 3. 키워드 학습 패널

### 준비 (`77bca3d`, `9fd4aa3`)

- Gemini 호출과 응답 텍스트 추출을 `GeminiClient`로 분리했다. 퀴즈 프롬프트·스키마·오류 코드는 그대로 두었다.
- `PLANS.md`의 키워드 패널 계획을 실제 코드와 대조해 보완했다.

### 1단계: 설명 패널 (`dba1c50`)

- **API:** `POST /api/keywords/explain`
  - 노트 소유자인지 확인한다.
  - 학생별로 10분에 20회까지 허용한다.
  - 설명 3종(3줄 요약·쉬운 설명·전공 심화)과 연관 키워드를 정리해 준다.
- **자료 링크:** AI가 만든 URL은 쓰지 않는다. 허용한 사이트(위키백과 한/영, MDN, Google Scholar)의 검색 URL을 서버가 조립한다.
- **화면:**
  - 에디터에서 텍스트를 선택하면 메뉴가 뜬다.
  - 설명은 오른쪽 패널에 나온다. 커뮤니티 패널과 동시에 열리지 않는다.
  - 같은 키워드는 세션 캐시로 다시 요청하지 않는다.

### 2단계: 노트 언급과 문제 만들기 (`28a24ed`)

- **노트 언급:** `GET /api/keywords/mentions`
  - 같은 강의의 내 노트에서 키워드가 든 최상위 블록을 최대 10개, 미리보기와 함께 준다.
  - LIKE 검색은 `ESCAPE '!'`를 쓴다. MySQL은 `'\'` 리터럴을 이스케이프 문자로 해석하기 때문이다.
  - 목록을 누르면 해당 노트의 블록으로 이동한다. 원문 보기와 같은 `sourceBlockId` 이동을 쓴다.
- **문제 만들기:** 선택 메뉴나 패널에서 누르면 `QuizConfigModal`의 preset으로 선택 블록과 키워드 개념을 채운다. 요청 필드는 바꾸지 않았다.

### 3단계: 노트 적용과 화면 배치 (`bd1bea1`, `f725891`)

- **노트에 적용:** 설명을 해당 블록 바로 뒤에 인용 블록으로 넣는다.
  - 인용 블록에는 "AI 생성 설명 · {설명 종류}" 표시(기울임)가 붙는다.
  - 넣기 전에 확인 창이 뜬다(적용 / 적용 안 함).
- **화면 배치:** 좁은 화면에서는 오른쪽 패널(설명·커뮤니티)이 본문 위에 겹쳐 뜬다. 넓은 화면(xl)에서는 본문 옆에 둔다.
- **범위 조정:** 키워드 통계는 하지 않기로 했다. 오답노트의 취약 개념 카드로 대신한다.

### 실제 앱 확인

- Gemini 무료 등급 한도(하루 20회)를 다 써서 `429 RESOURCE_EXHAUSTED`가 났다.
- 그래서 설명이 성공하는 화면은 브라우저 안에서 `/keywords/explain` 응답만 대체해 확인했다.
- 언급 검색, 노트 적용, 문제 만들기 연계는 실제 API로 확인했다.

## 4. 운영 안정화

### 계획 점검 (`0646a95`)

새 `PLANS.md`(운영 안정화 및 학습 기능 보완)를 코드와 대조해 다음을 반영했다.

- **P0-2 파일 URL 만료:** 그대로 하면 기존 기능이 깨진다.
  - 서명된 URL이 노트 JSON과 공유 스냅샷에 저장되고, 퀴즈 생성도 저장된 서명을 다시 검증한다.
  - 그래서 "저장은 서명 없는 경로, 응답할 때 서명"으로 재설계해야 한다. 별도 승인 항목으로 둔다.
- **이미 된 일:** 다음 항목은 대부분 이미 되어 있어 남은 일로 범위를 좁혔다.
  - P0-1 비밀값을 환경 변수로 분리
  - P0-3 평문 비밀번호를 로그인 시 해시로 점진 전환
  - P2-2 페이지 단위 코드 분할
- **추가한 위험:**
  - 자동 저장 복구 버그
  - Gemini 무료 한도
  - 키워드 요청의 `courseId`·`blockId`를 검증하지 않는 문제

### 자동 저장 복구 버그 (`d39f30b`)

- **원인:** 로컬 백업의 `timestamp`(숫자 ms)와 서버 `updatedAt`(ISO 문자열)을 비교했다.
  - 숫자와 문자열 비교는 항상 false다.
  - 그래서 서버에 내용이 있는 노트는 백업이 한 번도 복구되지 않았다.
- **수정:** 시각 비교를 버리고 버전으로 비교한다.
  - 백업에 "어느 서버 버전 위의 편집인지"(`baseUpdatedAt`)를 함께 저장한다.
  - 열 때 그 값이 지금 서버 `updatedAt`과 같을 때만 백업을 복구한다.
  - 저장에 성공하면 같은 내용의 백업을 지우고, 기준 버전을 응답의 `updatedAt`으로 바꾼다.
  - 기준 버전이 없는 옛 형식 백업은 서버 내용이 있으면 쓰지 않는다.
- **백엔드:** `saveNote`가 `saveAndFlush`를 쓴다. `@UpdateTimestamp`는 flush 때 채워지는데, 그 전에는 응답의 `updatedAt`이 이전 값이었기 때문이다.
- **테스트:** vitest를 추가했다(복구, 서버가 바뀐 경우, 옛 형식, 저장 성공·실패).
- **실제 앱:** 저장 전에 새로고침해도 내용이 복구되는 것을 확인했다.

### 노출된 비밀값과 로그인 보안 (`e86669f`)

**점검 결과**

- 원격 저장소는 공개이고, 첫 커밋에 DB 비밀번호와 JWT secret이 있었다.
- 해시로 비교해 보니 두 값 모두 로컬 설정에서 그대로 쓰고 있었다. 누구나 임의 학번의 JWT를 만들 수 있는 상태였다.
- Gemini 키는 이력에 없었다.

**코드 변경**

- **파일 서명 키 분리:** `file.signing-secret`(`FILE_SIGNING_SECRET`)을 쓰고, 없으면 `jwt.secret`을 쓴다.
  - JWT secret을 바꿔도 이전 값을 서명 키로 두면 저장된 이미지 URL이 그대로 동작한다.
  - 서명은 상수 시간으로 비교한다(`MessageDigest.isEqual`).
- **로그인 실패 메시지 통일:** 학번이 없을 때와 비밀번호가 틀릴 때 모두 "학번 또는 비밀번호가 올바르지 않습니다."(401)를 보낸다.
  - 없는 학번도 더미 BCrypt 비교를 한 번 한다. 응답 시간으로 계정이 있는지 짐작하지 못하게 하려는 것이다.
- **로그인 시도 제한:** 같은 학번으로 15분 안에 5번 실패하면 429와 남은 시간을 안내한다.
  - 로그인에 성공하면 실패 기록을 지운다.
  - 기록은 서버 메모리에 둔다.
- **테스트:** `AuthServiceTest`와 `FileAccessSignerTest`에 케이스를 추가했다.

**운영 조치**

- **로컬 `application-local.yaml`:** `jwt.secret`을 새 값으로 바꾸고, `file.signing-secret`에 이전 값을 넣었다.
- **사용자 조치:** DB 비밀번호를 바꾸고, 환경 변수 `DB_PASSWORD`와 로컬 설정에 반영했다.
- **실제 앱 확인:**
  - 이전 secret으로 만든 토큰은 403으로 거부된다.
  - 로그인 실패 메시지가 하나로 같다.
  - 5번째 실패에서 429가 나온다.
  - 업로드한 이미지가 보인다.
  - 새 DB 비밀번호로 서버 기동과 로그인이 된다. `local` 프로필과 기본 프로필 모두 확인했다.

**사고 기록**

- 비교 스크립트에서 PowerShell 함수 이름 `H`가 `Get-History` 별칭과 겹쳤다.
- 그 오류 메시지에 새 DB 비밀번호가 출력됐다. 그래서 DB 비밀번호를 한 번 더 바꿔야 한다.

- **사용자 조치**
  - DB 비밀번호 재교체(위 사고). MySQL 계정, `DB_PASSWORD`, `application-local.yaml` 세 곳을 바꾼다.
  - MySQL `bind-address=127.0.0.1`. 지금은 모든 인터페이스(`0.0.0.0:3306`)에서 대기한다.
  - 다른 배포 환경이 있다면 그쪽의 `JWT_SECRET` 교체. 이때 `FILE_SIGNING_SECRET`에 이전 값을 넣는다.
  - git 이력 재작성(선택). 값을 교체했으므로 공개 이력은 이미 무력하다.
- **결정 필요**
  - Gemini 한도 정책: 유료 전환 / 가벼운 모델로 분리 / 사용자별 하루 상한
  - P0-2 파일 URL 만료를 "응답 시 서명" 재설계까지 진행할지
- **결정 없이 할 수 있는 일**
  - Gemini 429를 "연결할 수 없습니다" 대신 한도 초과 안내와 별도 오류 코드로 구분
  - 한 번도 로그인하지 않은 평문 비밀번호 계정 일괄 전환, 그 뒤 평문 비교 경로 제거
  - 키워드 설명 요청의 `courseId`·`blockId` 검증과 권한 회귀 테스트
