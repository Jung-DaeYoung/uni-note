# 2026-10-31 작업 내역

오늘은 화면 디자인 통일과 애니메이션 정리를 했다.

- 로그인 화면 접근성 개선과 재설계
- 대시보드 재설계, 사이드바 아이콘 정리
- 사이드바·게시판 패널, 편집기 메뉴, CBT 화면 애니메이션 정리
- 블록 메뉴를 가리던 키워드 메뉴 수정
- 학습 보관함, 오답노트, 마이페이지, 공유 게시판 디자인 통일

진행 순서는 화면마다 같다: 검토·재설계 → 테스트(`npm test`·`lint`·`build`) → 로컬 서버와 Chrome에서 확인 → 커밋. 백엔드와 API는 바꾸지 않았다.

브랜치는 `feature/note-ai`이다.

## 1. 로그인 화면 (`73447ec`)

- **접근성:** 라벨과 입력창을 연결하고, `autoComplete`를 지정하고, 포커스 표시를 보이게 했다. 문서 언어는 `lang="ko"`로 바꿨다.
- **오류 표시:** 모달 대신 폼 안에 `role="alert"`로 보여 주고, 실패하면 학번 입력창으로 포커스를 옮긴다.
- **디자인:** 흰 배경이 눈부시다는 의견에 따라 흰 면을 없앴다. `slate-900` 배경 가운데에 로고와 폼을 두고, 어두운 배경에서 읽히도록 포커스·오류 색만 `blue-400`, `red-400`을 쓴다.
- **문구:** 라벨을 `학번`, `비밀번호`로 통일하고 placeholder를 없앴다.
- `LoginPage.test.jsx`를 추가해 라벨 연결, 인라인 오류, 포커스 이동을 확인한다.

## 2. 대시보드와 사이드바 (`1a21a5a`)

- **대시보드:** 마지막으로 수정한 노트를 어두운 패널로 크게 보여 주고, 나머지 노트·수강 강의·게시글은 줄 목록으로 바꿨다.
- 항목을 `div onClick`에서 실제 링크로 바꿔 키보드 이동과 새 탭 열기가 된다. 이동 경로는 그대로다.
- 눌러도 동작이 없던 `전체 보기` 버튼을 없앴고, 게시글 시간은 노트와 같은 "3시간 전" 형식으로 맞췄다.
- 게시글 영역의 보라색을 없애 슬레이트와 파란색으로 통일했다.
- **사이드바:** 메뉴·강의·노트 앞의 장식 아이콘을 없앴다. 화살표, `+`, 휴지통은 유지하고 스크린리더용 `aria-label`을 붙였다.

## 3. 애니메이션 (`1a21a5a`, `9729c0b`)

| 위치 | 변경 |
|---|---|
| 사이드바 | 폭 애니메이션 제거, 바로 접히고 펼쳐짐 |
| 게시판 패널 | 폭 고정, 위치만 전환. 열기 240ms, 닫기 180ms |
| 노트 본문 | 여백·폭 전환 제거 |
| 슬래시 메뉴 | 애니메이션 제거, 방향키가 즉시 반응 |
| 블록 핸들 | 위치 이동 애니메이션 제거 |
| 블록 메뉴 | `starting:`으로 150ms 등장 |
| CBT 버튼 | 필요한 속성만 전환, 눌림 97% |
| CBT 보기 | 색만 100ms 전환 |

- Tailwind v4의 `translate-x`, `scale`은 `transform`이 아니라 별도 CSS 속성을 쓴다. `transition-[transform]`으로는 움직이지 않아 `translate`, `scale`을 지정했다.
- `animate-in`, `zoom-in` 등을 제공하는 플러그인이 프로젝트에 없어, 이 클래스들은 실제로 동작하지 않고 있었다.
- 닫힌 게시판 패널은 `visibility`로 숨겨 Tab으로 들어가지 않는다.

## 4. 블록 메뉴를 가리던 키워드 메뉴 (`5f63a4a`)

- **증상:** 블록 핸들을 누르면 "키워드 설명 | 문제 만들기" 메뉴가 함께 떠서 `복제하기`, `삭제하기`를 가렸다.
- **원인:** 핸들은 블록 전체를 선택(`NodeSelection`)하는데, 키워드 메뉴가 이것을 텍스트 선택과 구분하지 않았다.
- **수정:** `getKeywordSelection`에서 `NodeSelection`을 제외했다. 일반 텍스트 선택에서는 메뉴가 그대로 뜬다.
- **확인:** 수정을 잠시 뺀 코드에서 버그가 재현되는 것을 대조 실험으로 확인했다. 블록 종류별 클릭·재클릭, 복제, 삭제, 드래그, 더블·트리플 클릭에서 메뉴가 잘못 뜨지 않았다.
- 핸들과 글자 사이(약 4px)를 더블·트리플 클릭하면 텍스트가 선택되어 메뉴가 뜬다. 텍스트 선택 동작이라 그대로 뒀다.

## 5. 화면 디자인 통일 (`0a71b97`)

공통 방향은 카드·장식 아이콘을 없애고, 슬레이트와 파란색, 기능 아이콘, 다크 모드를 유지한 줄 구분 목록이다. 앱 전체 Tailwind 테마는 건드리지 않고 화면별 CSS만 추가했다. 공통 스타일은 `QuizLibraryPage.css`의 `lib-` 클래스로 함께 쓰므로, 이 파일을 고치면 여러 화면이 같이 바뀐다.

- **학습 보관함:** 문제 모음을 강의별로 묶고, 풀이 기록은 점수를 크게 앞세웠다. 풀이 기록 행은 버튼으로 바꿔 Enter로 열 수 있다.
- **오답노트:** 요약 수치 4개, 오늘의 복습 목록, 취약 강의·유형·개념 막대 순서로 배치했다. 오답노트 모음은 한 줄 목록으로 바꿨다. `25% · 4회`는 기존 테스트가 확인하는 문구라 그대로 뒀다.
- **마이페이지:** 이름을 페이지 제목으로 올리고, 활동 히트맵 칸을 16px로 키워 통계 옆에 뒀다.
- **공유 게시판:** CBT 시험·노트 공유 목록과 노트 상세를 맞췄다. 눈 아이콘을 없애면서 숫자에 "조회"를 붙였다. 댓글 컴포넌트는 CBT 결과 화면과 함께 쓰므로 바꾸지 않았다.

## 6. 도구

- 디자인 스킬 `hallmark`, `emil-design-eng`를 로컬에 설치해 사용했다. `hallmark`는 설치 도구의 Gen 평가가 High Risk, Snyk 평가가 Med Risk로 나왔고 그 이유는 확인하지 못했다. 스크립트 일부를 읽어 본 범위에서는 악성 징후를 찾지 못했다.
- 스킬 파일, `.hallmark/` 작업 폴더는 커밋하지 않았다.
- 전역 스타일 변경을 피하려고 Hallmark의 전역 스캐폴드는 쓰지 않았고, 별도 에이전트 최종 리뷰도 돌리지 않았다.

## 7. 확인 결과

- 커밋한 코드 그대로 별도 폴더에 풀어 확인했다: 테스트 126개, `npm run lint`, `npm run build` 통과.
- 화면별로 Chrome에서 실제 입력으로 확인했다(1920·1024·375px, 다크 모드, 빈 상태, 키보드).

**확인하지 못한 것**

- 데이터가 많은 실제 계정의 화면과 실제 쓰기 요청. 학습 보관함·오답노트·공유 게시판의 데이터 화면과 쓰기 요청은 API를 예시 데이터로 대체해 확인했다.
- 애니메이션의 체감. 시간과 위치는 측정했지만, 긴 실제 노트에서의 끊김은 보지 못했다.

## 8. 남은 일

- **모바일 첫 화면:** 사이드바가 펼쳐진 채 시작해 본문이 좁아진다. `AppLayout`에서 작은 화면은 접힌 채 시작하도록 고쳐야 한다.
- **대시보드:** 제목 없는 노트가 큰 패널에 "제목 없음"으로 표시된다. 로딩 상태도 없어 빈 문구가 잠깐 보일 수 있다.
- **폰트:** `Pretendard`가 지정되어 있지만 폰트 파일이 없어 시스템 폰트로 대체될 수 있다. CSP가 외부 폰트를 막으므로 파일을 직접 포함해야 한다.
- **블록 메뉴:** Esc로 닫히지 않는다. 편집기 바깥을 눌러 닫으면 블록 전체 선택이 남는다.
- **코드 블록 언어 메뉴:** `CodeBlockComponent.jsx`에 동작하지 않는 `animate-in`이 남아 있다.
- **접근성:** 노트 항목의 휴지통은 마우스를 올려야 보여 키보드로는 보이지 않는다.
- **문구:** 네트워크 오류에도 "학번과 비밀번호를 확인해주세요"가 나온다. 난이도는 `MEDIUM`처럼 영어로 표시된다.
