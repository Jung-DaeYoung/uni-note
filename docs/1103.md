## 1. 배포 구조

```text
Netlify (React 빌드)
  └─ https://uninote.duckdns.org → EC2 Nginx :443 (Certbot)
       └─ 127.0.0.1:8080 → Docker: Spring Boot (/app/uploads → /opt/uninote/uploads)
            └─ AWS RDS MySQL 8.4
```

- 상세 절차는 `docs/배포환경 설계.md` 12장(실행 가이드라인)을 따른다.
- 컨테이너가 하나라 Docker Compose는 쓰지 않고 `docker run`으로 실행한다.

## 2. API 도메인: DuckDNS (`9922858`)

- Netlify가 HTTPS라 API도 HTTPS여야 하고(mixed content 차단), Certbot 인증서에는 도메인이 필요하다.
- 도메인 없이 하는 방법은 모두 탈락했다. Netlify 프록시는 약 26초 제한이라 최대 90초 걸리는 AI 퀴즈 생성이 실패한다.
- 무료 DuckDNS `uninote.duckdns.org`로 확정했다. Elastic IP는 바뀌지 않으므로 DuckDNS IP 자동 갱신 cron은 쓰지 않고, HTTPS 인증서 자동 갱신(certbot systemd timer)은 유지한다.

## 3. Docker 빌드 설정 (`0a189ab`)

- `backend/Dockerfile`, `backend/.dockerignore`를 설계 문서 4장 그대로 추가했다.
- `.dockerignore`로 비밀값이 든 `application-local.yaml`을 이미지에서 제외한다.
- `gradlew`는 `.gitattributes`로 LF가 보장되고, 실행 권한은 Dockerfile의 `chmod +x`로 처리한다.
- 로컬에 Docker가 없어 빌드는 아직 검증하지 못했다. 첫 검증은 EC2에서 한다.

## 4. AWS 리전: 시드니 고정 (문서 반영, 미커밋)

- 개인 계정을 기본 가입 방식(Sign up for AWS (new))으로 만들면 연락처 국가로 리전이 정해지고, 한국은 시드니(`ap-southeast-2`)로 고정된다.
- 서울로 바꾸려면 유료 플랜 전환 후 advanced features 활성화(되돌릴 수 없음) 또는 계정 재생성이 필요하다. 이득이 적어 시드니를 쓴다.
- EC2, EBS, VPC, RDS, AWS Backup은 사용 가능하다. Data Lifecycle Manager가 막히면 AWS Backup으로 대체한다.
- 무료 플랜 계정은 6개월 경과 또는 크레딧 소진 시 자동으로 닫히고, 90일 뒤 데이터가 삭제된다. 발표 일정과 크레딧 잔액을 함께 확인한다.

## 5. AWS 진행 상황

완료:

- DuckDNS `uninote.duckdns.org` 생성
- EC2 보안 그룹 `uninote-ec2-sg`: SSH 22(내 IP), HTTP 80, HTTPS 443(Anywhere IPv4). 8080은 열지 않음
- RDS 보안 그룹 `uninote-rds-sg`: MySQL 3306을 `uninote-ec2-sg`에서만 허용
- EC2 설정 입력: Ubuntu Server 24.04 LTS, 키 페어 `uninote-key.pem`(`C:\Users\DYJ\.ssh\`), 퍼블릭 IP 활성화, EBS 20 GiB gp3

확인 필요:

- EC2 인스턴스 시작 버튼을 눌러 실제로 생성됐는지 확인하지 못했다.

## 6. 다음 작업

한 단계씩 진행하고 확인한다.

1. EC2 콘솔 → 인스턴스에서 생성 여부 확인

4. RDS MySQL 8.4 생성: 같은 VPC, 퍼블릭 액세스 끔, 자동 백업 켬, `uninote-rds-sg`만 연결

6. 도구 설치: `docker.io nginx certbot python3-certbot-nginx mysql-client git` (Compose 불필요)

그 다음은 설계 문서 12장 3단계(로컬 DB 덤프·업로드 파일 이전, `backend.env` 작성, 이미지 빌드)다.

## 주의사항

- `FILE_SIGNING_SECRET`은 로컬 `application-local.yaml`의 `file.signing-secret` 값을 그대로 쓴다. 바꾸면 기존 이미지와 PDF가 403이 된다.
- DB 비밀번호, `JWT_SECRET`, `GEMINI_API_KEY`는 EC2의 `/opt/uninote/backend.env`에만 둔다. 코드와 GitHub에 올리지 않는다.
- `legacy-allowed-files`의 파일 3개가 로컬에 없다. DB 이전 전에 처리 방법을 정한다.
