## 6. 운영 안정화 [전달]

| 작업 | 내용 |
|---|---|
| Nginx timeout | 443 블록 `proxy_read_timeout` 120s → 180s. 백업은 `uninote.bak-20261107` |
| 업로드 제한 | 80·443 양쪽 `client_max_body_size 11m` 확인 |
| Swap | `/swapfile` 2GB 생성, `/etc/fstab` 등록 |
| Docker 로그 | compose에 `json-file` `max-size 10m`, `max-file 3` 추가 후 재생성, `docker inspect`로 확인 |
| JWT secret | 공개 이력(`764c07f`)의 값과 비교해 `DIFFERENT`, 길이 64자 |

- Nginx를 180초로 늘린 이유: 퀴즈 생성은 Gemini를 최대 2번 호출한다. 첫 응답이 30초 안에 오고 품질 문제가 있으면 한 번 더 생성하므로, 최악의 경우 약 150초가 걸린다. 120초면 Nginx가 먼저 504를 반환하는데, 백엔드는 퀴즈를 저장하므로 사용자가 다시 시도하면 중복이 생긴다. [확인 · `QuizService.java:45,48`]

## 7. 코드 분석 결과 (수정하지 않음) [확인]

| 항목 | 판단 |
|---|---|
| `Using generated security password` 경고 | `UserDetailsService` 빈이 없어 Spring이 기본 계정을 만든 것이다. httpBasic·formLogin이 없어 쓸 수 없는 계정이라 영향 없음 |
| 토큰 만료·누락 시 403 | 인증 실패 응답을 따로 지정하지 않아 기본값 403이 나간다. 프론트는 401에서만 로그아웃하므로, 24시간 뒤 토큰이 만료되면 앱이 조용히 실패한다. 원래 있던 동작이고, 고치려면 상태 코드 변경 승인이 필요하다 |
| 메모리 `-Xms256m -Xmx768m` | t3.small에 적절하다. Java 프로세스는 약 1.0~1.3GB를 쓴다. 서비스 중 `docker build`는 swap 없이는 OOM 위험이 있었다 |
| `TZ` | compose `environment`에 없다. 앱은 `Clock.systemDefaultZone()`으로 시각을 만들므로, TZ가 없으면 저장 시각이 UTC가 된다 [미확인] |
| `client.js`의 `ngrok-skip-browser-warning` 헤더 | 이제 필요 없지만 동작에는 영향이 없어 나중에 정리한다 |
