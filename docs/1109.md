## 6. AWS 인증 방식 결정 (OIDC 분석)

- 이 계정은 "Sign up for AWS (new)" 방식으로 만든 계정입니다. SCP는 AWS가 관리합니다.
- Free Tier SCP `DenyIAMRestrictedActions`가 `iam:*Provider*`를 막습니다. 그래서 OIDC Provider를 만들 수 없습니다. Paid 플랜도 같은 제한이 있습니다.
- **결정한 방식:**
  - IAM User `uninote-github-deploy`를 만들고 Access Key를 발급합니다.
  - `ssm:SendCommand`는 인스턴스 `i-0bf5c3061e672a073`와 커스텀 문서 `UniNote-Deploy`로만 제한합니다.
  - 결과 조회용 `ssm:GetCommandInvocation`, `ssm:ListCommandInvocations`만 Resource `*`로 둡니다.
  - `AWS-RunShellScript` 문서는 허용하지 않습니다.
  - 키는 GitHub Environment `production`(main만 허용)에 보관하고 주기적으로 교체합니다.

**결정이 필요한 항목**
1. **compose 이미지 참조 방식**
   - (A) compose를 그대로 둠(권장): GHCR 이미지를 pull한 뒤 `uninote-backend:latest`로 태그만 다시 붙이고, 직전 이미지는 `:prev`로 보존합니다.
   - (B) compose의 `image`를 `ghcr…:${IMAGE_TAG}` 형태로 바꿉니다.
2. **EC2의 GHCR 토큰 보관 방식**
   - (A) root로 수동 1회 `docker login`(권장): 인증 정보가 `/root/.docker/config.json`(권한 600)에 저장됩니다. base64 인코딩일 뿐 암호화되지 않습니다.
   - (B) Parameter Store SecureString: EC2 Role 수정이 필요합니다.
3. **헬스체크 기준**: Actuator와 health 엔드포인트가 없습니다.

7. IAM 정책 시뮬레이터로 확인한 뒤 IAM User와 Access Key를 만듭니다.
8. GitHub Environment `production`과 Secret을 설정합니다.
9. ci.yml에 `deploy` job을 추가하고 PR로 병합합니다.
10. 자동 배포 성공, 실패, 롤백을 검증하고 이미지 정리 정책을 적용합니다.

## 9. 보안 위험과 예방책

| 단계 | 위험 | 예방책 |
|---|---|---|
| GHCR PAT | 유출되면 Private 패키지를 읽을 수 있음 | `read:packages`만 부여, 만료일 설정, `--password-stdin` 사용 |
| deploy.sh | SSM이 root로 실행하므로 스크립트가 바뀌면 root 권한을 얻음 | root 소유 755, `set -euo pipefail`, SHA 형식 재검증, `set -x` 금지 |
| SSM Document | 임의 명령 실행 | 커스텀 문서만 허용, `allowedPattern` 적용 |
| IAM Access Key | 장기 키 유출 | 리소스 ARN 제한, 주기적 교체, CloudTrail 감사 |
| GitHub Secrets | PR이나 다른 브랜치에서 키에 접근 | Environment `production`을 main 전용으로 설정 |
| Actions 로그 | 민감 정보 노출 | 결과 줄만 출력, 로그는 tail 몇 줄만 |
| 동시 배포 | concurrency가 SHA별이라 배포가 겹칠 수 있음 | deploy job에 `concurrency: deploy-prod`, `cancel-in-progress: false` 설정 |

## 10. 운영 서비스와 RDS 보호

- **RDS 스키마:** prod는 `ddl-auto: validate`라서 앱이 스키마를 바꾸지 않습니다. 스키마가 맞지 않으면 기동에 실패하고, 이를 계기로 롤백합니다.
- **사용 금지 명령:** `compose down -v`, `docker volume rm`, `docker system prune -a`, `docker image prune -a`
- **롤백 지점:** `pre-cd`(최초), `prev`(직전 배포)
- **자원:** t3.small에서 컨테이너를 교체하는 방식이라 짧은 다운타임이 생깁니다. 이미지는 약 570MB입니다. 정리 정책이 필요합니다.

## 11. 최종 자동 배포 아키텍처

```
PR(main) → CI: Backend ∥ Frontend
main push → CI → image(GHCR :<sha>)
          → deploy (environment: production, concurrency: deploy-prod)
              IAM User 키 → ssm:SendCommand UniNote-Deploy(ImageTag=<sha>)
              → ssm:GetCommandInvocation으로 결과 확인
EC2 (root) /opt/uninote/deploy.sh <sha>
   pull → latest를 prev로 보존 → <sha>를 latest로 → compose up -d → 헬스체크
   성공: 오래된 이미지 정리 / 실패: prev로 복귀 후 exit 1
Netlify: Frontend는 기존 방식 유지
```
