# 좁은 화면 패널 겹침 + 키워드 설명 삽입 (키워드 학습 패널 3단계)

## 1. 좁은 화면에서 오른쪽 패널을 겹쳐 띄우기

**문제:** 커뮤니티 패널과 키워드 패널은 열릴 때 노트 영역을 400px 밀어낸다(`mr-[400px]`). 창 폭이 770px이면 사이드바까지 빼고 노트 영역이 114px로 줄어, 글자가 한 줄에 한 글자씩 꺾인다.

**수정:**
- `CourseDetailPage`: 노트 영역의 여백을 `xl:mr-[400px]`로 바꾼다. 1280px 이상에서만 노트를 밀어내고, 그보다 좁으면 패널이 노트 위에 겹쳐 뜬다. 패널은 이미 `fixed` 배치다.
- `CourseBoardPanel`, `KeywordExplainPanel`: `max-w-full`을 추가해 아주 좁은 창에서도 패널이 화면 밖으로 나가지 않게 한다.
- 커뮤니티 패널 최대화 동작은 그대로 둔다.

## 2. AI 설명을 현재 노트에 삽입 (PLANS.md 3단계)

- **패널 버튼:** 현재 탭의 설명 아래에 "노트에 삽입" 버튼을 둔다.
  - 설명을 만든 노트(`target.noteId`)를 지금 편집하고 있을 때만 버튼을 켠다. 노트를 옮겨 패널만 남아 있으면 "설명을 만든 노트에서만 삽입할 수 있습니다"라고 안내한다.
  - 삽입하면 "노트에 삽입했습니다"를 표시한다.
- **삽입 형태:** 기존 노드만 쓴다(새 Tiptap 노드 없음, DB 변경 없음). `blockquote` 안에 다음을 넣는다.
  - 설명 문단: 첫 문단은 `키워드: `로 시작하고, 설명에 빈 줄이 있으면 문단을 나눈다.
  - 마지막 문단: 기울임체 `AI 생성 설명 · {탭 이름}`. 출처가 AI 생성임을 표시한다.
- **삽입 위치:** 선택했던 최상위 블록(`target.blockId`) 바로 뒤다. 블록을 찾지 못하면 문서 끝에 넣는다.
- **편집기 연결:** 삽입은 `insertContentAt` 편집 명령으로 한다.
  - 블록 ID는 기존 `BlockId` 플러그인이 새로 붙인다.
  - 저장은 기존 자동 저장(debounce) 흐름을 탄다. 저장에 실패하면 헤더의 기존 저장 상태·재시도 UI가 그대로 보인다.
- **구조:**
  - `NotionEditor`에 `onEditorReady(editor)`를 추가한다. `CourseDetailPage`는 편집기를 ref로 들고 있다가 패널의 삽입 요청을 처리한다.
  - 삽입 로직은 `components/editor/insertKeywordExplanation.js`에 둔다(위치 계산과 노드 구성).

## 검증

- **vitest:**
  - `insertKeywordExplanation`: 블록 뒤 삽입, 블록이 없으면 문서 끝, 빈 줄로 문단 나누기, AI 표시 문단
  - 패널: 버튼 활성·비활성, 현재 탭의 텍스트와 탭 이름 전달
- `npm run lint`, `npm run build`, `npm run test`. 백엔드는 바뀌지 않는다.
- **브라우저:**
  - 좁은 창에서 두 패널이 겹쳐 뜨고 노트 폭이 유지되는지
  - 삽입한 인용 블록이 자동 저장되고, 새로고침 뒤에도 남는지(`GET /api/notes/{id}`로 확인)
