# 객관식 보기 품질 개선 (PLANS.md P2-5)

## 문제와 목표

현재 프롬프트는 객관식 보기를 어떻게 만들지 지시하지 않는다. 그래서 정답 보기만 길고 구체적이거나, 오답 보기가 노트와 무관해 쉽게 지워지거나, "모두 정답" 같은 단서형 보기가 나올 수 있다. 이런 보기는 개념을 몰라도 맞힐 수 있어, 정답률과 개념별 취약도(P2-3)를 왜곡한다.

이번 단계는 프롬프트에 객관식 보기 작성 규칙을 추가한다.

## 범위

포함:

- `QuizAiGenerationService.requestQuiz`의 엄격 준수 사항에 7번 규칙 추가, `PROMPT_VERSION` 갱신
  - 오답 보기는 노트에 나온 다른 개념이나 학습자가 흔히 혼동하는 내용으로 만든다.
  - 정답 보기만 길거나 구체적이지 않게 모든 보기의 길이와 문장 형태를 비슷하게 맞춘다.
  - "항상", "절대", "모두 정답", "정답 없음"처럼 답을 짐작하게 하는 표현과 보기를 쓰지 않는다.
- 프롬프트 고정 테스트 갱신

제외:

- 서버 검증 규칙 추가. 보기 길이 차이나 단서 표현은 문맥에 따라 정당할 수 있어 재생성 사유로 삼으면 AI 호출 비용만 늘어난다. 먼저 프롬프트로 개선하고, 실제 생성 결과를 보고 필요할 때 검증을 추가한다.
- 응답 스키마·DTO·DB·프론트 변경 없음

## 검증

- `QuizAiGenerationServiceTest.requestQuizPromptIsUnchanged` 갱신
- `backend\gradlew.bat test`
- 로컬 서버에서 실제 Gemini로 객관식을 생성해 보기 길이 균형, 단서 표현, 오답 보기가 노트의 다른 개념인지 확인
