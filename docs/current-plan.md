# 키워드 노트 언급·문제 만들기 연계 (PLANS.md 키워드 학습 패널 2단계)

## 문제와 목표

1단계 패널은 키워드를 설명하기만 한다. 이번 단계는 두 가지를 더한다.

1. 같은 강의의 내 노트 중 이 키워드가 나오는 위치를 보여 주고, 누르면 그 블록으로 이동한다.
2. 선택한 블록과 키워드를 채운 상태로 기존 AI 문제 생성 창을 연다.

## 백엔드

- **`GET /api/keywords/mentions?keyword=&courseId=`** → `KeywordMentionResponse[]` (`noteId`, `noteTitle`, `blockId`, `preview`)
  - **검색 조건:** 요청 학생의 노트이면서 해당 강의의 노트만 찾는다.
  - **후보 노트:** `NoteRepository`에 쿼리를 추가해, `searchContent`에 키워드가 들어 있는(대소문자 무시) 노트를 최근 수정 순으로 최대 10개 가져온다. 키워드의 `%`, `_`는 이스케이프한다.
  - **블록 찾기:** 후보 노트의 `content`(Tiptap JSON)에서 최상위 블록 단위로 텍스트를 모아 키워드가 든 블록을 찾는다. `blockId`는 블록의 `attrs.id`이고, 없으면 null이다.
  - **미리보기:** 일치 위치 앞뒤 40자이고, 잘린 쪽에 "…"를 붙인다.
  - **결과 수:** 전체 최대 10개다.
  - **입력 검증:** 키워드가 비었거나 80자를 넘으면 400 `INVALID_REQUEST`다.
  - **본문 파싱:** 노트 본문이 깨져 있으면 그 노트만 건너뛰고 경고 로그를 남긴다. 검색은 읽기 전용이라 요청을 실패시키지 않는다.
- AI를 호출하지 않으므로 호출 제한 대상이 아니다.

## 프론트엔드

- **`useKeywordMentions(target)`:** 언급 목록을 불러오고 로딩·오류·빈 상태를 둔다.
- **`KeywordExplainPanel`:**
  - "노트 언급" 목록을 보여 준다(노트 제목과 미리보기). 항목을 누르면 `/course/:courseId/note/:noteId`로 이동하고 `state.sourceBlockId`를 넘긴다. 이 이동 방식은 기존 원문 보기(`useSourceBlockScroll`)와 같다.
  - 헤더에 "문제 만들기" 버튼을 둔다.
- **`KeywordSelectionMenu`:** "문제 만들기" 버튼을 추가한다. 키워드 설명 버튼과 달리 80자 제한이 없다.
- **`QuizConfigModal`:** `preset`(`{ noteId, blockId, keyword }`)을 받는다.
  - 창을 열 때 범위를 채운다. 블록 ID가 있으면 그 블록만, 없으면 노트 전체다.
  - 키워드가 30자 이하이면 집중 개념에 넣는다.
  - 블록 목록을 아직 불러오지 않은 노트도 요청에 넣을 수 있게, 요청을 만들 때 저장본 블록 순서가 없으면 선택값을 그대로 쓴다.
  - 생성 요청의 필드는 바꾸지 않는다.
- **`CourseDetailPage`:**
  - `quizPreset` 상태를 두고, 창을 닫으면 비운다.
  - 노트를 이동해도 키워드 패널을 유지한다. 언급을 눌러 다른 노트로 가도 패널이 남게 하기 위해서다.

## 검증

- **백엔드:**
  - 언급 검색의 블록·미리보기·10개 제한·id 없는 블록·깨진 노트 건너뛰기
  - LIKE 이스케이프
  - 키워드 검증
  - 학생·강의 조건 쿼리 호출
- **프론트:**
  - 언급 목록 렌더링과 이동
  - 메뉴의 문제 만들기 버튼
  - 모달 `preset` → 요청의 `blockSelections`·`focusConcepts`
- **명령:** `backend\gradlew.bat test`, `npm run lint`, `npm run build`, `npm run test`
- **브라우저:** 선택 → 패널 언급 목록 → 이동·하이라이트, 문제 만들기 → 모달 범위 확인
  - Gemini 무료 한도가 남아 있으면 실제 생성까지 확인한다.
- `docs/api.md`를 갱신한다.
