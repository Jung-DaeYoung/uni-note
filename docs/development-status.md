# UniNote 개발 현황

## 구현된 기능

- 학번·비밀번호 로그인과 JWT 인증
- 수강 강의 기반 대시보드 조회
- 강의별 계층형 Tiptap 노트 생성·조회·수정·삭제
- 노트 자동 저장과 localStorage 임시 복구
- 노트 블록 ID, 페이지 링크, 이미지·파일 업로드
- 강의별 익명 게시글·댓글 작성·수정·삭제
- 노트 기반 퀴즈 생성·저장·조회·삭제
- 퀴즈 풀이 제출, 점수·답안 저장, 풀이 조회
- 오답노트 그룹 생성·삭제·문항 제거·재풀이

## 현재 문제점

- 백엔드 자동화 테스트는 Spring context 로딩 테스트 1개뿐이다.
- 프론트엔드 자동화 테스트가 없다.
- `QuizService`에 외부 AI 요청, 콘텐츠 처리, 응답 변환, 저장 책임이 집중돼 있다.
- `CourseDetailPage`와 `NotionEditor`에 화면 상태, CRUD, 저장·업로드·퀴즈 로직이 집중돼 있다.
- 노트·게시글·퀴즈의 수강 및 소유자 검증 흐름이 서비스별로 일관적인지 추가 확인이 필요하다.
- 설정 파일에 DB 접속 정보와 JWT secret이 직접 존재하며, 일부 서버 URL이 코드에 하드코딩돼 있다.
- 예외 처리에서 `IllegalArgumentException`이 인증 오류로 일괄 매핑되는 경로가 있다.

## 테스트 현황

- Backend: `backend/src/test/.../BackendApplicationTests.java`의 context 로딩 테스트
- Frontend: `package.json`에 `lint`, `build` 스크립트가 있으나 자동화 테스트 파일은 확인되지 않는다.
- 핵심 인증·권한·노트 저장·게시글 작성자·퀴즈 응답 파싱 경로의 회귀 테스트가 부족하다.

## 우선 개선 사항

1. DB·JWT·외부 연동 설정을 환경별로 분리하고 인증·권한·예외 응답을 명확히 구분한다.
2. API 계약을 유지하면서 인증·권한, 노트 저장, 게시글 작성자, 퀴즈 저장 경로의 백엔드 테스트를 추가한다.
3. `QuizService`의 콘텐츠 처리·외부 요청·응답 변환·저장 책임을 분리한다.
4. `CourseDetailPage`와 `NotionEditor`의 책임을 기능 단위로 나누고 API 호출 중복을 줄인다.

## 기준

기능 상태와 문제점은 현재 소스·설정 기준이다. `docs/refactoring-plan.md`의 파일 수와 과거 우선순위는 참고 자료로만 사용한다.
